# 角色画像（Personas）— 小说仿写生成应用

**版本**：1.1
**日期**：2026-04-27
**Depth**: Standard（角色名 + 背景 + 目标 + 痛点 + 使用场景 + 所需能力）

> **Changelog v1.1**：移除 Guest persona（未登录访客不作为独立角色，相关登录/注册作为 RegularUser 的前置状态处理）。

---

## P1. RegularUser（创作者）

| 字段 | 内容 |
|---|---|
| **角色名** | RegularUser |
| **背景** | 网络文学爱好者、自由撰稿人、内容创作者；具备基础互联网使用能力；未必懂 AI 技术 |
| **目标** | 上传或搜索参考小说 → 理解其风格 → 生成新小说（全新仿写或续写） → 在线阅读、编辑、导出 |
| **痛点** | 担心章节前后矛盾；担心生成内容跑题或脱离风格；不想被长时间等待卡住；希望可随时干预 |
| **使用场景** | 1) 上传 EPUB，选择类型模板，触发分析；2) 调节风格滑块后生成大纲并审核；3) 按章节审阅 Critic 建议，接受或打回重写；4) 导出成 EPUB 分享 |
| **所需能力** | 注册/登录、小说上传/下载 / URL 抓取、分析报告查看、风格配置、模式切换（仿写/续写）、大纲审核、章节审阅与编辑、导出 TXT/EPUB/Markdown、查看自己的历史任务 |

## P2. TeamMember（团队协作成员）

| 字段 | 内容 |
|---|---|
| **角色名** | TeamMember |
| **背景** | 与 RegularUser 同属一个 team/organization（例如小说工作室、编辑团队）；可能具备编辑、校对、排版等专职技能 |
| **目标** | 共享团队的原始小说库与生成任务；对同事生成的章节提供编辑与反馈；避免重复劳动 |
| **痛点** | 不能清晰看到同事的任务进度；担心自己的修改被覆盖；不想跨团队看到无关内容 |
| **使用场景** | 1) 查看 team 内共享的小说库；2) 打开同事创建的生成任务，查看大纲与章节；3) 在章节上评论/编辑；4) 关闭浏览器后再回来继续编辑 |
| **所需能力** | team 内所有小说与任务可见、基于权限的查看/编辑、任务协作视图（谁在审阅哪个章节）、评论/备注 |

## P3. Admin（平台管理员）

| 字段 | 内容 |
|---|---|
| **角色名** | Admin |
| **背景** | 平台运维与治理责任人；了解后端架构、AWS 账号、Bedrock 成本结构 |
| **目标** | 管理用户与团队、配置分析模板与模型策略、监控全局健康度与成本、校准类型标签库 |
| **痛点** | 成本失控；模型更新时需要灵活切换；类型标签随时间膨胀需合并；团队间纠纷需仲裁 |
| **使用场景** | 1) 在 admin 后台查看所有 team 的任务；2) 为"章节生成"切换到 Claude Sonnet 4.7；3) 新增"赛博朋克"类型模板；4) 查看 Observability 面板，识别慢任务；5) 审核并合并类型标签 |
| **所需能力** | 跨 team 全局视图、用户/团队 CRUD、任务阶段-模型映射配置、类型与分析模板管理、全局监控面板、审计日志查询 |

---

## P4. ContentModerator（内容审核员）

| 字段 | 内容 |
|---|---|
| **角色名** | ContentModerator |
| **背景** | 受平台或 team 委托的人工审核员；熟悉内容合规红线（色情、暴力、政治、未成年人保护等） |
| **目标** | 在章节发布/导出前，对 AI 生成内容做合规审查；标记敏感段落；必要时打回重写 |
| **痛点** | 敏感段落散落在大量文本中，难以快速定位；自动过滤工具的 false positive/negative |
| **使用场景** | 1) 从审核队列进入待审章节；2) 查看 AI 预标记的敏感段落；3) 逐段判定通过/修改/打回；4) 在后台筛选所有已审核/未审核任务 |
| **所需能力** | 审核队列视图、段落级高亮与批注、打回操作、审核历史查询；只读访问作品与 team 元数据（不能修改业务内容） |

              ▼ 平台层
       ┌──────────────┐

       └──────────────────┘
